# ShreeMadhav AI Advisor (website assistant)

A floating **"Ask ShreeMadhav AI"** assistant on every public page. Visitors can
type or speak a question, hear the reply, and request a consultation. It is free
to run: no paid APIs, no subscriptions and no keys in the browser.

## How it answers

| Mode | When it is used | What visitors see |
|---|---|---|
| **Demo mode** (default) | Always available, including the current Vercel-only deployment | The website text that best matches the question, with a link to the page it came from. Labelled *Demo mode: answers are matched directly from the website content, not generated by an AI model.* |
| **AI model** (optional) | When the backend has a free self-hosted model configured (see below) | An answer generated by that model from the same website content. Labelled *AI model*. If the model fails, the assistant falls back to demo mode automatically. |

**Source of truth.** Answers are built from the website's own content, so they
update when the website copy changes. The assistant reads from:

- `frontend/src/i18n/locales/en.js`, `hi.js` and `site.*.js`
- the services list from `/api/services`, falling back to the built-in list
- the public settings, such as address, phone and email

**Never invented.** Universities, courses, fees, scholarships, deadlines, visa
rules, destination lists and success rates are not published on the website.
Questions about them get an honest answer: the information isn't published, the
team can confirm it, and no outcome is guaranteed. Both modes follow these rules.
In AI mode, the backend's system prompt also enforces them (see
`backend/src/services/assistant.service.js`).

**Languages.** English and Hindi. A question written in Devanagari is answered
in Hindi from the Hindi website text. The EN / हिं switch also sets the
language for voice input and spoken replies.

## Voice

The assistant uses the browser's built-in Web Speech API, which is free.

- **Voice input** works in Chrome, Edge and Safari. It needs HTTPS and starts
  only when the visitor clicks the microphone button. Firefox doesn't support it,
  so the assistant shows a message there and text chat keeps working.
- **Spoken replies** use the device's own voices. The mute setting is
  remembered. Hindi replies need a Hindi voice installed on the device. If there
  isn't one, the assistant says so and shows the reply as text.
- Clear messages appear when the microphone is blocked, missing or silent, when
  voice isn't supported, and when there's no internet connection.

## Consultation requests

When a visitor asks for counselling or admission help, the assistant offers a
**Request a Consultation** button. The form collects:

- name
- email
- phone
- preferred destination
- course of interest
- preferred counselling time

It submits through the **existing** `POST /api/contact` endpoint as enquiry type
`education`, so requests appear in **Admin → Enquiries**. There's no new
database table. Success is shown only after the server confirms the request.
If the API can't be reached, as on the current Vercel-only deployment, the form
says nothing was sent and links to the Contact page.

## Local development

No extra steps. The usual `npm run dev` runs the assistant in demo mode.

## Optional: connect a free self-hosted AI model

The backend can call any free model server you run yourself. Two options:

### Ollama (simplest)

1. Install Ollama from <https://ollama.com>. It runs on Windows, macOS and Linux.
2. Download a small model, for example:
   ```bash
   ollama pull llama3.2:3b     # about 2 GB; runs on a CPU with 8 GB RAM
   ```
   For better Hindi answers, try a larger multilingual model such as
   `qwen2.5:7b` (about 16 GB RAM recommended).
3. In `backend/.env`:
   ```env
   ASSISTANT_PROVIDER=ollama
   ASSISTANT_BASE_URL=http://127.0.0.1:11434
   ASSISTANT_MODEL=llama3.2:3b
   ```
4. Restart the backend. `GET /api/assistant/status` should return
   `{"enabled": true, ...}`, and the assistant will show **AI model** instead of
   **Demo mode**.

### OpenAI-compatible self-hosted servers

This covers llama.cpp `llama-server`, LM Studio, vLLM, LocalAI and similar.

```env
ASSISTANT_PROVIDER=openai-compatible
ASSISTANT_BASE_URL=http://127.0.0.1:8080
ASSISTANT_MODEL=<model name your server expects>
ASSISTANT_API_KEY=   # only if your server requires one; stays on the server
```

**Resources.** The model has to run on a machine you control: a VPS or office
server with at least 8 GB RAM for a 3B model. Typical free hosting tiers (Vercel,
Railway free) can't run a model. Without one, the assistant stays in demo mode.

**Security.** Model URLs and keys are read only by the backend. The browser
talks only to `/api/assistant/*` on this site, and nothing from the chat is
stored.

## Deployment

### Vercel (frontend only, current setup)

No changes needed. Push to `main` and Vercel rebuilds. The assistant appears on
every public page in demo mode, and consultation requests point visitors to the
Contact page until the backend is live.

### With the backend (Railway or a VPS, see `DEPLOY.md`)

1. Deploy the backend as described in `DEPLOY.md`.
2. Add the `/api` rewrite to `frontend/vercel.json`, before the existing
   catch-all rule.
3. Consultation requests are then submitted for real and appear in
   **Admin → Enquiries**.
4. Optional: set the `ASSISTANT_*` variables on a server that can reach your
   model to switch on **AI model** mode.

## Customising

- **Interface text:** `assistantStrings.js`
- **Search hints:** `KEYWORDS` in `knowledge.js`, extra search words per topic
- **Answers for sensitive topics:** `POLICY` in `engine.js`
- **Model rules:** `SYSTEM_PROMPT` in `backend/src/services/assistant.service.js`
- **Facts:** don't add them to the assistant. Update the website content and the
  assistant picks up the change automatically.
